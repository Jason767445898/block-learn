# 基于 GMGN K 线逆向分析钱包交易策略的规划

## 1. 目标

目标不是“读心”判断钱包真实想法，而是用可验证的数据，把钱包在每笔交易前后的市场环境还原出来，给出高置信度的行为解释。

希望回答的问题：

- 为什么买：买入前是否出现上涨、放量、回踩、突破、低位反弹、连续阴跌等信号。
- 买多少：仓位大小是否和信号强度、历史胜率、波动率、流动性、前序盈亏有关。
- 为什么平仓：卖出是否发生在冲高、回撤、跌破入场价、止盈、止损、时间止损、分批出场等情境。
- 为什么亏损平仓：是快速止损、流动性恶化、买入后无延续、跌破关键 K 线，还是被动割肉。
- 为什么加仓：加仓发生在浮盈扩大、回踩确认、跌后摊平、突破加速，还是固定分批建仓。

最终产物应当是每个 token position 的结构化分析，而不是只输出几个全局标签。

更进一步，这个项目的根本目标是从“解释钱包行为”走向“验证能否复刻它的盈利策略”。因此后续实现不能停留在事后归因，而要把每条推断规则变成可回测、可过滤、可执行、可风控的策略条件。

需要注意：复刻某个盈利钱包不等于复刻盈利。链上看到的是结果，不一定能看到它的完整信息优势、下单速度、私有信号、资金规模、滑点、失败交易、多个关联钱包协同和撤单逻辑。尤其是 pump.fun 这类高波动资产，策略是否还能盈利必须通过样本外回测和小资金实盘验证。

## 2. 想法的合理性

这个方向是合理的，因为钱包交易策略通常会在成交点附近留下可观察痕迹：

- 买在当前 K 线高位，且前几根 K 线持续上涨，通常更像追涨或动量交易。
- 买在当前 K 线低位，且前面已经大幅下跌，通常更像抄底或接飞刀。
- 买入前成交量突然放大，说明可能在跟随市场热度或机器人信号。
- 卖出发生在买入后短时间内亏损，且没有明显反弹，可能是严格止损或超短线失效退出。
- 卖出发生在冲高回落后，可能是没有卖到最高点，但仍属于趋势出场。
- 多次买入同一个 mint，可以区分为突破加仓、回踩加仓、亏损摊平或固定分批。

但需要明确：K 线只能解释“市场状态”，不能单独证明“主观原因”。例如，一个钱包在放量阳线买入，可以推断为“动量/放量确认型买点”，但不能证明它一定是看到了某个群消息或 insider 信号。

## 3. 可行性判断

### 可直接实现

当前项目已经具备基础条件：

- 用 Bitquery 获取钱包在 pump.fun 的交易记录。
- 用 GMGN 获取相关 token 的 K 线。
- 已有 `analyze-kline` 命令，可以把成交点匹配到 K 线，计算位置、动量、量能、买入后最大浮盈和最大回撤。

因此 MVP 可行，而且不需要先做复杂前端。

### 需要补强的数据

只下载“当前 K 线和前一根 K 线”不够。要解释平仓、亏损平仓和加仓，至少需要三段 K 线：

- 买入前窗口：用于判断为什么买。
- 持仓期间窗口：用于判断是否有加仓、是否经历浮盈/回撤。
- 卖出后窗口：用于判断卖出效率，例如是否卖飞、是否及时止损。

建议最小窗口：

- 1m K 线：买入前 10-20 根，买入后直到最后一次卖出，再额外延长 10-20 根。
- 如果持仓超过 30-60 分钟，可以补充 5m K 线，避免 1m 噪音太多。

### 主要风险

- GMGN K 线价格单位可能是 USD，Bitquery 交易价格是 SOL/token，不能直接混用价格数值。
- GMGN API 可能超时，需要缓存 K 线，避免每次重复请求。
- pump.fun 早期 token 波动极大，单根 K 线的 high/low 可能非常夸张，指标需要抗异常值。
- 钱包可能通过多个地址协同操作，单地址分析会漏掉完整意图。
- 如果只看 K 线，不看 LP、发币、迁移、持仓分布，很容易把项目方/做市行为误判成普通交易策略。
- 直接跟单会遇到延迟、滑点和流动性不足问题。该钱包买入时可盈利，不代表你晚几秒或更大仓位买入仍然有同样收益。
- 目标钱包的收益可能来自少数极端盈利 token。如果只复制表层入场规则，可能复制到大量亏损样本，却错过真正贡献利润的少数交易。

## 4. 数据设计

### 交易数据

每条交易至少需要：

```text
wallet
mint
tx_hash
timestamp
side: buy/sell
sol_amount
token_amount
trade_price
```

其中 `trade_price` 在 GMGN K 线模式下主要用于参考，不建议和 GMGN USD K 线直接比较。

### K 线数据

每根 K 线至少需要：

```text
mint
timestamp
open
high
low
close
volume
resolution
```

建议后续增加：

```text
source
quote_currency
fetched_at
```

这样可以区分 GMGN、CSV、其他数据源，也能处理价格单位问题。

### Position 数据

按 `wallet + mint` 聚合：

```text
first_buy_time
last_sell_time
buy_count
sell_count
total_buy_sol
total_sell_sol
realized_pnl_sol
holding_seconds
entry_events
add_events
exit_events
kline_window
```

后续分析应以 position 为主，因为单笔 trade 无法完整解释加仓和平仓。

## 5. 核心分析逻辑

### 5.1 为什么买

对第一笔买入，计算买入前窗口：

- 前 N 根 K 线涨跌幅。
- 当前 K 线在前 N 根 high/low 区间的位置。
- 当前成交量相对前 N 根均量的倍数。
- 是否突破前高。
- 是否从低点反弹。
- 买入前是否连续上涨或连续下跌。

可输出标签：

- `放量追涨买入`
- `突破前高买入`
- `回踩后买入`
- `低位反弹买入`
- `连续下跌中接入`
- `无明显 K 线信号`

### 5.2 买多少

买入金额需要和上下文一起看：

- 单笔买入 SOL。
- 相对该钱包最近 N 笔平均买入的倍数。
- 同一 mint 是否分批买入。
- 买入时波动率是否较高。
- 买入前量能是否放大。
- 前一笔/当天已实现 PnL 是否为正。

可输出判断：

- `固定小仓位试错`
- `信号增强时加大仓位`
- `亏损后降低仓位`
- `盈利后放大仓位`
- `高波动仍重仓，风险偏好高`

注意：如果没有钱包总资产或资金曲线，只能分析“相对历史交易仓位”，不能准确判断真实仓位占比。

### 5.3 为什么加仓

对同一个 mint 的第二次及后续 buy，计算加仓时相对第一次买入的价格变化：

- 加仓时价格高于首次买入：可能是突破加仓或浮盈加仓。
- 加仓时价格低于首次买入：可能是摊平成本或补仓。
- 加仓发生在回踩后重新上破：可能是回踩确认。
- 加仓间隔很短、金额相似：可能是拆单或机器人分批执行。

可输出标签：

- `浮盈加仓`
- `突破加仓`
- `回踩确认加仓`
- `亏损摊平`
- `固定拆单建仓`

### 5.4 为什么平仓

对每次 sell，计算卖出前后的窗口：

- 卖出价相对持仓期间最高价的位置。
- 卖出前 N 根 K 线动量。
- 卖出时是否跌破买入后局部低点。
- 卖出前是否出现放量下跌。
- 卖出后 M 根 K 线继续上涨还是继续下跌。

可输出标签：

- `冲高止盈`
- `回撤止盈`
- `快速止损`
- `跌破入场区止损`
- `时间止损`
- `分批减仓`
- `卖飞`
- `有效避险`

### 5.5 为什么亏损平仓

亏损卖出需要单独分析，因为它最能体现纪律和风险控制：

- 从首次买入到卖出的时间是否很短。
- 卖出前最大浮盈是否曾经为正。
- 卖出前最大回撤是否超过阈值。
- 卖出时是否跌破前低或入场 K 线 low。
- 卖出后是否继续下跌。

判断逻辑示例：

- 持仓很短、亏损较小、卖出后继续下跌：`有效快速止损`。
- 曾经大幅浮盈但最后亏损卖出：`盈利回撤未及时止盈`。
- 买入后一路下跌并亏损卖出：`动量失败退出`。
- 跌很多后才卖，卖出后反弹：`恐慌止损或迟到止损`。

## 6. MVP 实现方案

### 第一阶段：Position 级 K 线报告

新增或增强 `analyze-kline`，让输出从“逐笔 trade context”升级为“逐个 position context”。

每个 position 输出：

- mint
- 首次买入时间
- 最后卖出时间
- 买入次数、卖出次数
- 总买入、总卖出、PnL
- 首次买入原因标签
- 加仓原因标签
- 平仓原因标签
- 亏损平仓原因标签
- 最大浮盈、最大回撤
- 卖出效率
- 简短解释

示例输出：

```text
- 8BiTGG...pump pnl -0.5000 SOL
  entry: 放量追涨买入，买入前 5m 涨幅 42%，成交量为均量 3.1x
  sizing: 中等仓位，约为该钱包最近买入均值 0.9x
  exit: NoSell，当前仍未卖出或样本窗口内未捕捉到卖出
  risk: 买入后最大回撤 -38%，最大浮盈 +6%
```

### 第二阶段：从解释报告提炼可复刻规则

把自然语言标签转成可执行条件，例如：

```text
entry_rule:
  buy only when:
    pre_5m_return > 30%
    volume_spike > 2.0
    range_position > 70%
    wallet_buy_amount between 0.3 and 0.8 SOL

exit_rule:
  take profit when:
    pnl > 30% and price falls 20% from local high
  stop loss when:
    pnl < -15% or no new high within 90 seconds

sizing_rule:
  base size = median wallet buy size
  reduce size when token volatility is extreme
```

这些规则要进入回测，而不是只作为描述。

### 第三阶段：回测与样本外验证

复刻策略前必须回答：

- 如果按推断规则买入所有符合条件的 token，历史收益是否接近目标钱包。
- 去掉最大盈利的 1-3 笔后，策略是否仍然盈利。
- 换一段时间、换一批 token 后，规则是否仍然有效。
- 加入滑点、手续费、延迟后是否仍然盈利。
- 同样规则在亏损 token 上为什么失效。

建议输出指标：

```text
total_pnl
win_rate
average_roi
median_roi
max_drawdown
profit_factor
largest_win_share
avg_holding_seconds
slippage_adjusted_pnl
```

如果最大盈利贡献超过 50%-70%，说明策略可能高度依赖少数 jackpot，复刻难度很高。

### 第四阶段：K 线缓存

新增本地缓存目录：

```text
data/cache/gmgn/
```

缓存文件建议：

```text
data/cache/gmgn/<mint>_<resolution>_<from>_<to>.json
```

好处：

- GMGN 超时时可以复用已下载数据。
- 同一个钱包反复分析不会重复请求。
- 后续可以离线复盘。

### 第五阶段：多周期确认

1m K 线适合看超短线，但噪音大。建议支持：

- `--resolution 1m`：分析精确买卖点。
- `--higher-resolution 5m`：判断更大级别趋势。

如果 1m 显示追涨，但 5m 仍处在突破早期，则结论应从“高位追涨”修正为“短线突破跟随”。

### 第六阶段：结合行为分析

把 `behaviors` 的 LP、发币、swap、transfer 结果接入最终报告：

- 有 create token + add LP：优先标记为项目方/流动性管理钱包。
- 有大量 swap 但无 LP：更像交易钱包。
- 有 close account 或频繁转账：可能是资金归集或机器人清理账户。

这一步能降低误判。

### 第七阶段：纸面交易和小资金验证

即使回测有效，也不应直接大仓位实盘。建议分三步：

1. 纸面交易：程序只记录“此刻应该买/卖”，不发交易。
2. 小资金验证：固定极小仓位，验证延迟、滑点、成交失败和真实 PnL。
3. 风控上线：限制单笔亏损、单日亏损、最大并发持仓、最大连续亏损。

只有当实盘小资金结果和回测接近，才有资格讨论扩大仓位。

## 7. 推荐命令形态

初始 MVP 可以继续用现有命令：

```bash
cargo run -- analyze-kline <wallet> \
  --trades-source bitquery \
  --kline-source gmgn \
  --days 3 \
  --limit 10 \
  --resolution 1m \
  --lookback 20 \
  --lookahead 20
```

后续可以新增更明确的命令：

```bash
cargo run -- explain-strategy <wallet> \
  --trades-source bitquery \
  --kline-source gmgn \
  --days 7 \
  --limit 50 \
  --resolution 1m
```

`explain-strategy` 可以专门输出“为什么买、为什么卖、为什么加仓、为什么亏损卖”的解释型报告。

## 8. 判断规则示例

### 买入原因

```text
if momentum_5m > 0.30 and volume_spike > 2.0 and range_position > 0.70:
    放量追涨买入

if momentum_5m < -0.30 and current_close > previous_close and range_position < 0.35:
    低位反弹买入

if current_high > previous_n_high and volume_spike > 1.5:
    突破前高买入
```

### 加仓原因

```text
if add_price > first_buy_price * 1.10:
    浮盈加仓

if add_price < first_buy_price * 0.90:
    亏损摊平

if add_interval_seconds < 20 and amount_similar:
    固定拆单建仓
```

### 平仓原因

```text
if pnl > 0 and exit_efficiency > 0.70:
    高效止盈

if pnl > 0 and drawdown_from_peak > 0.30:
    回撤止盈

if pnl < 0 and holding_seconds < 120:
    快速止损

if pnl < 0 and sell_after_breakdown:
    跌破结构止损
```

## 9. 结论

你的思路可行，而且是当前 MVP 的自然下一步。最关键的调整是：不要只取“当前 K 线和前一根 K 线”，而要围绕每个 position 获取完整的买入前、持仓中、卖出后的 K 线窗口。

这样才能从单点成交分析升级为策略解释：

- 买入前窗口解释“为什么买”。
- 买入金额和历史交易分布解释“买多少”。
- 持仓期间路径解释“为什么加仓”。
- 卖出前后窗口解释“为什么平仓”。
- 亏损卖出后的价格走势解释“止损是否有效”。

如果目标是复刻盈利，那么 MVP 的优先级应调整为：

1. 先做 position 级解释报告。
2. 再把解释标签转成可执行规则。
3. 然后做回测和样本外验证。
4. 最后才进入纸面交易和小资金实盘。

也就是说，真正要复刻的不是某个钱包的每一笔交易，而是它可重复的入场条件、仓位规则、加仓规则、退出规则和风控规则。
